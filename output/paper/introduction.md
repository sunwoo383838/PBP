# 1 서론

LLM 기반 다중 에이전트 시스템은 역할·도구·이력이 서로 다른 에이전트에게 작업을 분배하고, 메시지 교환을 통해 분산된 정보를 통합한다 [Li 2023; Hong 2024; Qian 2024; Wu 2024; Guo 2024]. LLM 에이전트는 작업 기억(working memory)에 포함된 문맥을 바탕으로 추론하고 외부 행동을 수행하므로 [Sumers 2024], 다른 에이전트나 저장소의 정보는 메시지 또는 도구 관측을 통해 작업 기억에 반영되어야 현재 결정에 쓰일 수 있다. 따라서 시스템 수준의 정보 가용성은 개별 의사결정에서의 활용을 보장하지 않으며, 협업 성능은 분산된 정보의 발견·전달·선택에 의존한다.

기존 시스템의 정보 교환은 공유 문맥과 직접 메시징의 두 접근으로 나뉜다. 공유 문맥 접근은 전역 대화록 방송 [Wu 2024], 공유 메시지 풀 [Hong 2024], 블랙보드 [Han 2025], 전체 실행 이력 전달 [Cognition 2025]로 공동 가시성을 넓힌다. 직접 메시징에서는 역할 설명이나 에이전트 카드를 근거로 응답자를 고르고, 응답자는 국소 문맥과 도구 관측에 기반하여 답을 구성한다 [Wu 2024; A2A 2026]. 두 접근 모두 과제 관련 정보가 공유 범위 또는 선택된 응답자의 관측 범위 안에 있어야 작동하며, 정보가 분산된 조건에서 다중 에이전트 LLM의 성능은 완전한 정보를 받은 단일 에이전트에 크게 못 미친다 [Li 2026]. 본 논문은 과제 관련 정보의 실제 분포와 의사결정에 사용되는 문맥 사이의 불일치를 문맥 분절(context fragmentation)로 정의한다.

문맥 분절은 그룹 단위 권한 경계에서 특히 두드러진다. 본 논문은 부서·팀·테넌트·협력 조직과 같이 데이터 소유와 접근 정책을 공유하는 에이전트 집합을 하나의 그룹으로 추상화한다. 각 그룹은 자체 데이터베이스·규정·작업 로그를 유지하며, 외부 에이전트는 내부 기록을 직접 조회하는 대신 요청을 통해 허용된 정보를 얻는다. 이러한 권한 분할(authorization-partitioned) 설정은 내부 상태에 대한 직접 접근 없이 협업하는 A2A의 상호운용 모델 및 정책 기반 메모리 접근 제어에 부합한다 [A2A 2026; Rezazadeh 2025; Margalit 2026]. 통신 성능을 위해 그룹 구성을 최적화하는 연구 [Zhuge 2024; Chen 2026]와 달리, 본 설정의 그룹 경계는 소유와 권한이 부과하는 외생적 제약이다.

그룹 추상화는 외부 상호작용을 단순화하는 동시에 내부의 정보 분포와 상태 변화를 은닉한다(그림 1). 외부 요청자는 공개된 역할·능력 기술을 참조할 수 있지만, 지금 어떤 구성원이나 기록이 필요한 정보를 보유하는지는 관측할 수 없다. 또한 개별 응답자의 작업 기억은 문맥 용량과 이력의 요약·축출에 의해 제한되므로 [Packer 2023], 응답자의 국소 문맥이 그룹 전체의 관련 상태를 포괄한다는 보장은 없다. 그 결과 경계에서는 그룹 수준의 정보 가용성과 개별 응답 수준의 정보 포괄 사이에 간극이 생긴다. 그룹 내부에서는 문맥 공유와 기록 조회로 완화할 수 있는 분절이, 외부 요청자에게는 요청과 응답으로만 해소할 수 있는 구조적 제약으로 나타난다. 본 논문은 이 간극을 결정 필수 정보(decision-critical information)의 위치로 기술한다. 외부 요청자가 고를 담당자의 문맥에 정보가 이미 있다면 간극은 없고, 이 경우는 모든 비교의 대조군이 된다. 간극은 정보가 담당자 밖에 있을 때 생기며, 대표적으로 다음 조건에서 나타난다. 첫째, 업무 대행이나 인계로 명목상 담당자와 실제 보유자가 어긋난다. 둘째, 정보가 여러 구성원에 분산되고 보유 관계는 그룹의 작업 로그에만 기록된다. 셋째, 문맥 축출이나 보유자 이탈 이후 정보가 지속 기록에만 남는다. 이들 조건은 응답이 공유 데이터뿐 아니라 구성원의 진행 중 판단과 예외 처리에 의존할 때 더 어려워진다. 어느 경우든 그룹 안에 정보가 있더라도 특정 구성원에 대한 질의나 단일 정보원 조회만으로는 충분한 응답을 얻기 어렵다.

접근 통제 메모리는 기록의 조회·공유 정책을 지원하고 [Rezazadeh 2025; Margalit 2026], 분산 정보 수집 연구는 요청자 측의 협력자 탐색과 질의를 다룬다 [Jhamtani 2025]. 본 논문은 그룹 단위 권한 분할을 고정한 채, 응답 구성에 관여하는 두 결정의 관측 범위에 주목한다. 요청 중개(request mediation)는 응답자를 선택하고, 정보 선택(information selection)은 응답에 포함할 내용을 결정한다. 두 결정은 부분 관측(partial observability) 아래에서 이루어지며, 응답이 포괄할 수 있는 정보의 범위를 함께 제약한다. 이에 우리는 그룹 간 요청에서 결정 필수 정보가 어느 단계에서 누락되는지, 그리고 경계 내부의 기록 가시성이 각 손실을 얼마나 회복하는지 묻는다.

우리는 두 결정을 응답 그룹 내부의 기록에 근거하여 수행하는 pull by proxy를 제안한다. 내부 조회 권한을 가진 게이트웨이는 그룹 기록을 근거로 응답자를 고르고, 구성원 응답과 지속 기록을 통합한 요청 관련 그룹 범위 상태 표현에서 최종 답을 구성한다. 구성원 응답은 현재 작업 문맥의 정보를 제공하고, 지속 기록은 인계 관계와 개별 문맥에서 빠진 이력을 보완한다. 이 과정은 외부 요청자의 직접 조회 권한을 확대하지 않으며, 경계를 넘을 수 있는 정보의 허용 정책은 모든 경계 조건에서 같다. 또한 같은 선택 모듈을 게이트웨이가 아니라 개별 응답자에 부착한 구성과 비교하여, 선택 시점의 기록 가시성과 모듈 배치의 효과를 구분한다.

평가를 위해 우리는 결정론적 조직 시뮬레이터로 그룹·구성원·기록·과제를 생성하고, 과제마다 결정 필수 기록의 위치·보유자 상태·발견 가능성을 정답과 함께 주석한다. 요청자에게 전달된 결정 필수 정보의 포괄률(coverage)을 측정하고, 이 주석을 실행 관측과 대응시켜 정보 요구가 요청(request)·라우팅(route)·선택(select)·상태(state)·사용(use)의 다섯 관문을 지나는 동안 어디서 처음 손실되는지 식별한다. 두 결정은 개입 대상이고, 다섯 관문은 손실을 관측하는 체계이다. 기준 조직에서 카드 기반 직접 메시징은 결정 필수 기록이 담당자 문맥에 있는 과제의 72%를 맞히지만 그 밖에 있는 과제는 5%만 맞힌다. pull by proxy는 후자를 42%로 끌어올려 두 집단의 격차를 67pp에서 28pp로 줄이며(58% 회복, 다른 백본에서 47%), 전자는 통계적으로 변하지 않는다. 본 논문의 기여는 다음과 같다.

- **Boundary-Constrained Formulation.** 그룹 단위 권한 분할 아래의 정보 손실을 부분 관측에 따른 요청 중개와 정보 선택 문제로 정식화하고, 그룹 수준의 정보 가용성과 개별 응답의 정보 포괄 사이의 간극을 결정 필수 정보의 위치로 정의한다(3절).
- **Pull by Proxy.** 외부의 직접 조회 권한을 확대하지 않고, 그룹 기록 기반 중개와 구성원 응답·지속 기록의 통합을 수행하는 경계 메커니즘을 제안한다. 게이트웨이 구성과 응답자 부착 구성을 함께 제시한다(4절).
- **Labeled Benchmark.** 결정 필수 기록의 위치·보유자 상태·발견 가능성·변경 시각이 주석된 조직 시뮬레이터를 구축한다. 담당자가 이미 보유한 과제를 내부 대조군으로 포함하고, 반사실 정답으로 오답의 종류를 구분하며, 모든 실행은 결정론적으로 재생된다(5절).
- **Gate-Level Loss Localization.** 주석과 실행 관측을 대응시켜 최초 손실 관문을 식별하고, 중개와 선택을 한 칸씩 더하는 사다리 비교와 변형 실험으로 메커니즘별 회복 효과를 분리한다(5절).
- **Empirical Guidance for Boundary Design.** 경계 조건 전반에서 결정 필수 정보가 전달되지 않은 과제는 대부분 실패한다. 응답자의 동료 질의는 손실을 회복하지 못하고 조립 없는 원본 기록 전달은 부분적으로만 회복하는 반면, 그룹 기록 가시성 아래에서 두 결정을 수행하면 충분한 용량의 백본에서 가장 큰 회복을 보이며, 선택 모듈을 응답자에 부착해도 같은 효과를 얻는다. 이는 모듈의 배치보다 선택 시점의 그룹 기록 가시성이 주요 설계 요인임을 시사한다(6절).

## 원안 대비 변경 요약

1. 4문단: 대조군(담당자 보유)을 먼저 두고, 세 조건(B·C·D)과 운영 의존(C_ops)을 "더 어려워지는 조건"으로 분리 — §5 클래스 체계와 일치.
2. 4문단: "검색 결과가 포괄을 보장하지 않는다"는 구절 삭제 — 응답자 원본 검색 단독 조건은 실행하지 않았고, 검색+조립을 응답자에 부착한 sidecar는 Ingress와 동일.
3. 6문단: "응답의 공개 범위는 모든 비교 조건에서 동일" → "허용 정책은 모든 경계 조건에서 같다" — Full-load(분할 없는 참조)와 retrieve(원문 전달)를 정확히 포괄.
4. 7문단: 포괄률(coverage) 측정을 평가 서술에 유지. 헤드라인 한 문장(72% / 5% → 42%, 격차 67→28pp = 58% 회복) 추가. 나머지 수치는 §6.
5. 기여: Labeled Benchmark bullet 추가; "단일 요인 통제 비교" → "사다리 비교와 변형 실험"; 기여 5를 정성 서술로 바꾸고 "충분한 용량의 백본에서"로 9B 비회복을 예고; "가장 큰 회복"의 주어를 "두 결정을 그룹 기록 가시성 아래에서 수행하는 구성"으로 — Δ_route/Δ_sel 배분은 백본마다 다름(27B 5.4/15.0, DeepSeek 10.3/7.7).
