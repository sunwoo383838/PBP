# III. 프로젝트 결과 및 성과

> 실험 수치는 모든 실행 완료 후의 최종 결과임(2026-10-02, 1차 기준 셀 1~15일, G 셀·부록 1~10일). 원자료는 `output/` 1~5번 CSV, 요약은 `results_final.md`.
> 지표는 답 전체 정확 일치율(exact match)이며, 원리상 풀 수 없는 과제는 제외하고, 같은 시드에서 비교 조건이 모두 답한 공통 과제만 비교함.

---

## 1. 결과물의 주요 기능 및 특징

### 1.1 결과물 개요

- **그룹 경계 통신 실험 하네스(gbg)**: 권한으로 나뉜 LLM 에이전트 그룹 사이의 통신 방식을, 같은 업무 시나리오 위에서 바꿔 가며 결정적으로 실행하고 채점하는 실험 플랫폼임.
- 조건 사이에 다른 것은 **"그룹 경계를 넘는 방식" 하나**로 한정하고, 시나리오·모델·과제 예산·프롬프트 공통부·에이전트 기억 모델은 모두 같게 고정함.
- 구성 요소

| 구성 요소 | 역할 |
|---|---|
| 실행 엔진(커널) | 가상 시계(하루 3라운드), 메시지 버스(홉 상한), 과제 예산, 사건 기록(WAL), 체크포인트 재개 |
| 경계 모듈(게이트웨이) | 요청 해석, 그룹 기록 검색, 담당자 선택, 내부 질의, 답 조립, 재질의 |
| LLM 에이전트 루프 | 요청자·응답자 도구 호출 루프, 컨텍스트 구성(원문 창 + 요약), 형식 검사·재시도 |
| 검색기 | BM25 + 임베딩(bge-m3) RRF 결합, 재정렬(Qwen3-Reranker-8B), 증거 상한 |
| 시나리오 어댑터 | worldgen 4.4(주 벤치마크), grouped SILO 등 외부 벤치마크 연결 |
| 채점·분석 도구 | 정확 일치 채점, 도달 불가 과제 판정, 층화 분석, 부트스트랩 신뢰구간, CSV·Markdown 내보내기 |
| 실행·감시 도구 | 실행 진입점, 자동 재개 감시자, ALERT 자동 재기동, 진행률·비용 집계 |

### 1.2 주요 기능

**① 통신 조건 사다리**

| 조건 | 정의 | 고치려는 손실 |
|---|---|---|
| Direct | 요청자가 에이전트 카드를 보고 상대 그룹 에이전트에게 직접 질의, 답 조합도 요청자가 함 | 기준선 |
| Routing | 상대 그룹 게이트웨이가 그룹 기록으로 담당자를 골라 질문·답을 원문 그대로 중계 | 담당자 오지목(L_route) |
| Ingress | 게이트웨이가 여러 담당자에게 묻고 그룹 기록으로 답을 조립(최신 버전 판정, 충돌·제안 표시, 출처 인용), 부족하면 재질의 | 흩어진 사실·밀려난 기억·떠난 담당자(L_sel, L_state) |
| full_load (참조) | 권한 분할 없는 단일 에이전트, 조직 전체 기록 검색 | 권한을 모두 푼 참조점 |
| 부록 3종 | direct_relay(응답자가 동료에게 되물음), retrieve(조립 없이 근거 원문 전달), sidecar(에이전트마다 검색·조립 모듈) | 대표 반론 검증 |

- 조건은 설정 파일(`configs/conditions.yaml`)로 정의하며, 새 조건을 추가해도 기존 조건의 실행 결과가 바뀌지 않음을 기록 해시로 검증함.

**② 게이트웨이(경계 모듈)**

- 처리 단계: 요청 해석 → 별칭 해소 → 그룹 기록 하이브리드 검색 → 담당자 선택(인원 상한 없음, 과제 예산이 상한) → 내부 질의 → 조립 → 재질의.
- 권한 준수: 모든 기록 접근을 접근 표(`configs/access.yaml`)로 검사하며, 게이트웨이는 자기 그룹 기록만 읽음.
- 조립 출력: 담당자 답 + 기록 근거로 보탠 사실·충돌·제안 값·확인 불가 항목, 모든 값에 출처([R#] 응답, [E#] 기록, [V#] DB 버전) 인용. 근거가 풀리지 않는 제안은 코드가 버림.

**③ 결정적 실행과 재현성**

- 가상 시계·이름 붙은 난수 흐름·라운드 끝 고정 순서 커밋으로 실행 순서를 결정함.
- 사건 기록(WAL)과 해시로 실행 동일성을 판정하고, LLM 응답 캐시(LIVE / REPLAY / SCRIPTED)로 전 과정을 재생함.
- 중단 시 체크포인트에서 재개하고 진행 중 라운드는 캐시로 재생함. "30일 실행의 앞 15일 = 15일 실행"의 접두 동일성을 검증함.
- 동결 커밋 사본으로만 실행하고, 실행마다 설정·코드·시나리오 해시를 담은 매니페스트를 남김.

**④ 공정 비교 장치**

- 모든 조건에 같은 과제 예산(호출 300회, 토큰 400만, 요청자·응답자·게이트웨이 합산, 최종 답변 1회 예약)을 적용함.
- 모든 조건에 같은 에이전트 작업 기억(원문 8,000토큰 + 요약 2,000토큰), 같은 공통 프롬프트와 답 작성 규칙을 적용함.
- 병렬 호출이 최종 답변 예약분을 침범하지 않도록 진행 중 호출을 예산에 선반영함.

**⑤ 업무 시뮬레이션 벤치마크(worldgen 4.4) 연동**

- 도메인(HR·IT·재무·구매·법무) × 지역 그룹, 인사이동·대리 처리·작업자 생성·소멸이 있는 동적 세계.
- 과제마다 담당자 기억 상태 등급(A~D), 운영 기록 조각 결정 여부(C_ops), 걸린 그룹 수, 과제 종류(15종)를 기록해 사후 층화가 가능함.
- 정합성 불변식(I1~I17)·분포 기준(F1~F9) 검증과 정답 수작업 재계산 표본 검수로 평가 시나리오 36개를 검수함.

**⑥ 대규모 실행 운영**

- DeepInfra API 연동, 모델 별칭(Qwen3.5-27B·9B, DeepSeek-V4-Flash) 교체, thinking 끔·온도 0 일괄 적용.
- 요청 한도 초과(429)는 3초부터 지수 백오프 재시도, 같은 지점 반복 실패 시 ALERT, 일시 장애(잔액 부족 등) 후 자동 재기동.
- 실행 중 목표 일수 변경(체크포인트 재개), 진행률·비용·지연 집계.

**⑦ 채점과 분석**

- 정답 원장과의 답 전체 정확 일치로 채점, 원리상 풀 수 없는 과제 자동 제외.
- 실험 결과에 영향 없는 분석용 관측 기록: LLM 호출별 입력 구성, 게이트웨이 인용-근거 대응, 검색 점수, 경계 통과 메시지, 예산 사용량.
- 공통 과제 비교, 유형별 층화, 과제 단위 짝 부트스트랩 신뢰구간, 과제 단위 원자료 CSV(`output/5_task_level.csv`).

### 1.3 특징

1. **통제된 비교**: 조건 차이를 "경계를 넘는 방식" 하나로 좁히고, 담당자 선택 → 답 조합 → 재질의를 사다리로 쌓아 단계별 효과(Δ_route, Δ_sel)를 분리해 측정함.
2. **완전한 재현성**: 기록·캐시로 실행 전 과정을 재생할 수 있고, 코드 수정 때마다 기존 조건의 실행 결과가 바이트 단위로 같은지 검증함(회귀 테스트 326개).
3. **권한 경계 준수**: 정보가 경계를 넘는 경로를 메시지로만 한정해 "권한을 지키면서 손실을 얼마나 회복하는가"를 측정함.
4. **확장성**: 벤치마크는 어댑터, 조건은 설정 파일, 모델은 별칭으로 교체함.
5. **실험 규모**: 3개 모델 × 4개 조건(기준 셀), 그룹 수 5~15의 4개 셀, 부록 조건 3종, 평가 시드 3개 — 총 81회 실행.

## 2. 기술적 성과 및 차별점

### 2.1 실험 성과 (최종 결과)

**(1) 그룹 경계에서의 조립(Ingress)이 경계 정보 손실을 회복함**

기준 셀 D5·R2(그룹 10개), 1~15일

| 모델 | 과제 수 | Direct | Routing | Ingress | full_load | Ingress − Direct [95% 구간] |
|---|---|---|---|---|---|---|
| Qwen3.5-27B | 427 | 0.33 | 0.38 | **0.53** | 0.52 | **+0.20** [+0.16, +0.25] |
| DeepSeek-V4-Flash | 427 | 0.35 | 0.45 | 0.53 | **0.63** | **+0.18** [+0.13, +0.23] |
| Qwen3.5-9B | 427 | 0.19 | 0.23 | 0.25 | **0.38** | +0.06 [+0.02, +0.10] |

- 27B와 DeepSeek에서 Ingress가 Direct보다 약 0.2 높고 신뢰구간이 0과 충분히 떨어져 있음.
- 27B에서 Ingress는 권한을 모두 푼 참조점(full_load)과 같은 수준(0.53 대 0.52)에 도달함.

**(2) 효과는 설계 예측대로 "기억·운영 조각이 필요한 과제"에서만 나타남**

27B, 4개 셀 합산(기준 셀 15일 + G 셀 10일)

| 과제 유형 | 과제 수 | Direct | Routing | Ingress | full_load | Ingress − Direct |
|---|---|---|---|---|---|---|
| A 등급 (최근 기억에 원문 있음) | 483 | 0.68 | 0.66 | 0.67 | 0.75 | −0.01 |
| B 등급 | 238 | 0.11 | 0.36 | **0.59** | 0.43 | **+0.47** |
| C 등급 | 272 | 0.02 | 0.09 | **0.31** | 0.28 | **+0.29** |
| D 등급 | 169 | 0.02 | 0.08 | **0.33** | 0.30 | **+0.31** |
| C_ops (운영 조각 결정) | 270 | 0.01 | 0.08 | **0.30** | 0.24 | **+0.28** |

- A 등급에서는 차이가 없고(−0.01), B·C·D 등급과 C_ops에서만 큰 격차가 생김. 사전에 적어 둔 예측(Δ_sel은 A·B에서 ≈0, C·D에서 양수)과 구조가 일치함.
- 운영 기록 조각이 답을 가르는 과제에서 Direct는 사실상 0(0.01)인데 Ingress는 0.30으로 회복함.

**(3) 효과는 그룹 규모와 무관하게 일관됨**

27B, 1~10일

| 셀 | 그룹 수 | 과제 수 | Direct | Ingress | Ingress − Direct [95% 구간] |
|---|---|---|---|---|---|
| R1 | 5 | 141 | 0.30 | 0.48 | +0.18 [+0.10, +0.26] |
| D3 | 6 | 167 | 0.35 | 0.62 | +0.27 [+0.19, +0.35] |
| 기준 | 10 | 285 | 0.34 | 0.56 | +0.22 [+0.16, +0.29] |
| R3 | 15 | 427 | 0.29 | 0.48 | +0.20 [+0.15, +0.25] |

- 모든 셀에서 격차가 +0.18~0.27로 유의하게 양수이며, 셀 간 구간이 겹쳐 규모에 따른 차이는 구별되지 않음.
- 그룹당 하루 과제 수·그룹당 인원·에이전트당 과제 수를 셀 간 고정해, 규모 효과와 부하 효과를 분리함.

**(4) 대표 반론 검증(부록): 이득의 원천은 "그룹 기록을 보는 조립"**

27B 기준 셀, 1~10일, 7조건 공통 285과제

| 조건 | 전체 | B | C | D | C_ops |
|---|---|---|---|---|---|
| Direct | 0.34 | 0.16 | 0.02 | 0.00 | 0.02 |
| direct_relay (응답자가 동료에게 되물음) | 0.34 | 0.14 | 0.03 | 0.00 | 0.03 |
| Routing | 0.40 | 0.34 | 0.17 | 0.02 | 0.15 |
| retrieve (조립 없이 근거 원문 전달) | 0.47 | 0.48 | 0.25 | 0.21 | 0.22 |
| sidecar (에이전트마다 검색·조립) | **0.56** | 0.40 | **0.43** | 0.40 | **0.40** |
| **Ingress** | **0.56** | **0.52** | 0.40 | **0.49** | 0.37 |

- "응답자가 동료에게 물으면 된다"(direct_relay): Direct와 같음 → 기각.
- "그룹 단위 RAG일 뿐"(retrieve): 근거 원문만 넘기면 Ingress에 크게 못 미침 → 조립 단계의 기여 확인.
- "에이전트마다 붙이면 된다"(sidecar): 전체 정확도는 Ingress와 같음(0.56). Ingress는 B·D 등급(담당자 교체·이탈로 기록이 흩어진 경우)에서 높고, sidecar는 C 등급·C_ops에서 약간 높음. 정확도만으로는 우열이 갈리지 않아, 차별점은 비용·일관성·여러 담당자 종합 쪽에서 보여야 함(후속 분석).

### 2.2 기술적 차별점

| 구분 | 기존 접근 | 본 결과물 |
|---|---|---|
| 평가 대상 | 다중 에이전트 협업의 경로·궤적 적합성(예: EntCollabBench의 위임 경로 판정), 분산 계산의 합의 수렴(예: SILO-Bench) | **그룹 경계에서의 정보 손실과 그 회복**을 직접 측정 |
| 비교 통제 | 시스템 단위 비교(구조·프롬프트·도구가 함께 바뀜) | 조건 차이를 "경계를 넘는 방식" 하나로 한정, 예산·기억·프롬프트 공통 |
| 손실 귀속 | 최종 정답률 위주 | 과제마다 기억 상태 등급·운영 조각·걸린 그룹 수를 기록해 **어느 종류의 손실을 어느 단계가 고치는지** 층화 |
| 권한 모델 | 공유 메모리 또는 전역 접근이 흔함 | 접근 표로 모든 기록 접근을 강제, 권한을 지키는 조건과 권한을 푼 참조점(full_load)을 같은 틀에서 비교 |
| 재현성 | 실행마다 결과가 달라지는 LLM 비결정성 | 사건 기록·응답 캐시·체크포인트로 실행 전 과정 재생, 코드 수정 시 바이트 단위 회귀 검증 |
| 반론 처리 | 본 조건만 보고 | 대표 반론 3종(동료 되묻기, 단순 RAG, 에이전트별 부착)을 같은 틀의 조건으로 구현해 정량 검증 |

### 2.3 엔지니어링 성과

- 회귀 테스트 326개 통과, 기존 조건의 실행 결과 불변을 코드 수정마다 검증.
- 평가 시나리오 36개를 정합성·분포 기준과 정답 수작업 재계산으로 검수.
- 81회 실행(약 1만 2천 과제-실행)을 3개 모델·동시 수십 프로세스로 운영. 요청 한도·잔액 부족 등 외부 장애에서 데이터 손실 없이 자동 재개.
- 실행 중 발견한 결함을 원인 분석 후 수정하고 변경 이력(`HARNESS_CHANGES.md`)으로 관리(예: 병렬 호출의 예산 예약분 경합, 검색 유사도 부동소수 결정성).

### 2.4 검증된 범위와 한계

- **규모 효과 미검증**: 설계 단계 가설 "그룹 수·기간이 커질수록 효과가 커진다"는 지지되지 않음. 그룹 수 5~15에서 격차가 평평하고, 한 과제에 걸린 그룹이 많을수록 격차가 줄어듦(2개 +0.27 → 5개 이상 +0.08). 결과는 "규모와 무관한 회복 효과"로 정리함.
- **모델 의존성**: 9B 모델에서는 이득이 작음(+0.06). 게이트웨이가 모은 정보를 활용하려면 일정 수준 이상의 모델 능력이 필요함.
- **절대 정확도**: C·D 등급에서 Ingress도 0.3~0.4 수준으로, 회복은 부분적임.
- **알려진 구현 한계**: Ingress 조립이 담당자 답의 설명 글을 요청자에게 전달하지 않아 규칙 적용형 과제에서 일부 손해가 있음(분석으로 확인, 후속 수정 예정).
- **기간 축**: 비용 절감을 위해 기준 셀을 15일로 단축해 장기(16~30일) 효과는 일부 조건만 관측함.

## 3. 기대 효과

### 3.1 학술적 기대 효과

- **새로운 평가 축 제시**: 다중 에이전트 시스템 평가를 "경로가 맞았는가"에서 "권한 경계를 넘으며 무엇이 손실되고 어디서 회복되는가"로 확장함. 손실 유형(기억 상태·운영 조각)별 회복량이라는 측정 단위를 제공함.
- **재현 가능한 실험 기반**: 결정적 실행·기록 재생·동결 설정을 갖춘 하네스와 검수된 시나리오를 함께 제공해, 후속 연구가 같은 조건에서 새 게이트웨이 설계를 비교할 수 있음.
- **반론 검증 방법론**: "단순 RAG", "동료 되묻기", "에이전트별 부착" 같은 대안을 같은 틀의 조건으로 구현해 정량 비교하는 방식은 다른 아키텍처 주장 검증에도 적용 가능함.

### 3.2 산업적 기대 효과

- **엔터프라이즈 에이전트 설계 지침**: 부서·권한별로 에이전트를 나누는 기업 환경에서, 정보 회복 장치를 "요청자 쪽"이 아니라 "정보를 가진 그룹의 경계"에 두고 그 안에서 조립하는 것이 효과적임을 근거로 제시함. 특히 담당자 교체·인수인계·운영 메모처럼 기록이 흩어지는 업무에서 효과가 큼.
- **권한·보안 준수와 성능의 양립**: 권한을 풀어 모든 기록을 주는 방식(full_load)과 비슷한 정확도를, 권한 경계를 지키면서 달성할 수 있음을 보임. 데이터 접근 통제가 필요한 조직에서 설계 선택지를 넓힘.
- **비용 의사결정 근거**: 조건별 과제당 호출·토큰·성공당 비용을 함께 측정해, 정확도 이득과 운영 비용을 비교한 도입 판단을 지원함.
- **모델 선택 근거**: 경계 조립의 이득이 모델 능력에 따라 달라짐(27B·DeepSeek ≫ 9B)을 보여, 게이트웨이와 에이전트에 어느 수준의 모델을 배치할지 판단하는 데 활용 가능함.

### 3.3 활용 및 확장

- **도구로서의 재사용**: 어댑터만 추가하면 다른 업무 벤치마크(SILO 등)에 같은 조건 사다리를 적용할 수 있음.
- **후속 연구 과제**: Ingress 조립 개선(담당자 설명 글 보존, 대상 엔티티 확인), sidecar 대비 비용·일관성 비교, 여러 그룹이 걸린 과제에서의 조립 부담 완화, 장기(30일 이상) 효과 검증.
- **운영 자산**: 대규모 LLM 실험을 위한 자동 재개·장애 복구·비용 추적 도구는 다른 장기 실행 실험에도 그대로 활용 가능함.
